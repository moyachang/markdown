# 帶前綴的自動編號（@PrefixedId）

  

日期：2026-10-20

  

## 背景與需求

  

- `PROJECT_ID`、`ROL_ID` 等主鍵需要自動編號，並帶有前綴（如 `PRJ`、`ROL`），欄位長度為 `varchar(30)`。

- 客戶資料庫可能是 **MSSQL** 或 **Oracle**，編號機制必須兩者通用。

- 環境：Spring Boot 4.0 / Hibernate 7.1（`@GenericGenerator` 已不建議使用，改用 `@IdGeneratorType`）。

  

## 編號格式

  

採用 **前綴 + 12 位補零流水號**，例如 `PRJ000000000001`（共 15 碼）。

  

- 欄位維持 `varchar(30)`，保留日後調整格式的空間。

- 流水號來源為資料庫 **SEQUENCE**。

  

### 為何不用其他做法

  

| 做法  | 問題  |
| --- | --- |
| `MAX(ID) + 1` | 同時有多個請求時會產生重複編號 |
| Redis INCR | Redis 資料遺失後編號會從頭開始 |
| 資料庫 SEQUENCE（採用） | MSSQL 2012+ 與 Oracle 皆支援，同時有多個請求也不會重複 |

  

## 跨資料庫做法

  

取號 SQL 不寫死，而是交給 Hibernate Dialect 依資料庫產生：

  

```java

dialect.getSequenceSupport().getSequenceNextValString(sequence);

```

  

| DB | 產生的 SQL |
|---|---|
| MSSQL | `select next value for SEQ_UP4_PROJECT` |
| Oracle | `select SEQ_UP4_PROJECT.nextval from dual` |

  

- MSSQL 回傳 `Long`、Oracle 回傳 `BigDecimal`，程式統一以 `Number.longValue()` 處理。

- 使用哪個 Dialect 由 `application-mssql.yml` / `application-oracle.yml` 的 `database-platform` 決定。

  

## 新增的共用元件（common 模組）

  

位置：`common/src/main/java/com/flowring/common/infrastructure/persistence/jpa/id/`

  

| 檔案 | 用途 |
|---|---|
| `PrefixedId.java` | 註解，參數：`prefix`、`sequence`、`digits`（預設 12） |
| `PrefixedIdGenerator.java` | Hibernate generator，寫入時（INSERT）自動產生編號 |
| `SequenceIdGenerator.java` | Spring Bean，在程式中手動取號（`next(prefix, sequence, digits)`），供非主鍵欄位或需事先取得編號的情況使用 |

  

### 使用方式

  

```java

@PrefixedId(prefix = "PRJ", sequence = "SEQ_UP4_PROJECT")

@Column(name = "PROJECT_ID", columnDefinition = "VARCHAR(30)", nullable = false)

private String projectId;

```

  

```java

entity.setRolId(sequenceIdGenerator.next("ROL", "SEQ_UP4_ROL", 12));

```

  

## UP4_PROJECT 的套用與修正

  

### 編號規則

  

| 情境 | projectKey | projectId | version |
|---|---|---|---|
| 全新專案 | 由 `SEQ_UP4_PROJECT_KEY` 產生，例如 `PRK000000000001` | `@PrefixedId` 產生 `PRJ000000000001` | 由呼叫端帶入，例如 `v1.0` |
| 同專案新版本 | 帶入原本的值，不重新編號 | `@PrefixedId` 產生新的 `PRJ000000000002` | 由呼叫端帶入，例如 `v2.0` |

  

### 修改的檔案

  

| 檔案 | 修改內容 |
|---|---|
| `UP4ProjectJpaEntity` | 移除與 `@EmbeddedId` 衝突的 `@IdClass`；`id` 在建立物件時就先初始化；實作 `Persistable`（以 `@Transient newEntity` 判斷是否為新資料）；移除寫死 `"0001"` 的 `@PrePersist` |
| `UP4ProjectJpaEntityId` | `projectId` 加上 `@PrefixedId`；補上 `@NoArgsConstructor`、`@AllArgsConstructor`、`@EqualsAndHashCode`（JPA 對複合主鍵的要求） |
| `UP4ProjectMapper` | 補上 `ProjectStatus` / `ProjectRisk` / `ProjectChatGroup` 與 `Integer` 的轉換（原本的編譯錯誤）；補上 `projectId` / `projectKey` / `version` 與 `id.*` 之間的對應；`projectId == null` 時 `newEntity = true` |
| `SpringDataUP4ProjectRepository` | 主鍵型別由 `String` 改為 `UP4ProjectJpaEntityId`；新增 `findByIdProjectId`、`deleteByIdProjectId` |
| `JpaUP4ProjectRepositoryAdapter` | `save()` 在 `projectKey` 為空時以 `SequenceIdGenerator` 產生；改用 `findByIdProjectId` / `deleteByIdProjectId`；加上 `@Transactional` |
| `UP4ProjectRepository`（domain） | `save()` 由 `void` 改為回傳 `UP4Project`，新增時呼叫端可取得產生的 `projectId`、`projectKey` |
| `UP4ProjectMemLogMapper` | `toEntity()` 補上 `projectId` / `memId` / `version` 與 `projectMemLogJpaEntityId.*` 之間的對應（2026-10-21，詳見下方「相關修正」） |

  

### 需要特別注意的設計細節

  

1. **`id` 必須事先 new 好**：實測發現 Hibernate 會**先執行 generator，後執行 `@PrePersist`**。如果 `id` 是 null，generator 無法把 `projectId` 寫進去，會丟出 `PropertyAccessException`。

2. **為什麼需要 `Persistable`**：複合主鍵新增時，`id` 物件本身不是 null，Spring Data 的 `save()` 會誤判為舊資料而走 `merge`，`@PrefixedId` 就不會產生編號。實作 `isNew()` 讓 `save()` 新增時走 `persist`。從資料庫讀出或寫入後，`@PostLoad` / `@PostPersist` 會把旗標設回 `false`。

3. **為什麼欄位叫 `newEntity`**：如果欄位叫 `isNew`，Lombok 產生的 builder 方法與 getter 名稱會對不上，MapStruct 無法正確對應。

  

## 相關修正：UP4ProjectMemLogMapper 的複合主鍵對應（2026-10-21）

  

### 問題

  

編譯時 MapStruct 出現警告：

  

```

UP4ProjectMemLogMapper.java:[15,31] Unmapped target property: "projectMemLogJpaEntityId".

```

  

這不只是警告，而是真的有 bug。`toEntity()` 會把一般欄位一個個複製過去，但不會建立複合主鍵物件 `projectMemLogJpaEntityId`，因此：

  

- `projectId`、`memId`、`version` 都沒有寫進 Entity，寫入資料庫時主鍵為 null，會失敗。

- Entity 的 `getProjectId()`、`getMemId()`、`getVersion()` 會丟 `NullPointerException`。

  

### 修正

  

與 `UP4ProjectMapper` 相同做法，明確指定欄位對應：

  

```java

@Mapping(target = "projectMemLogJpaEntityId.projectId", source = "projectId")

@Mapping(target = "projectMemLogJpaEntityId.memId", source = "memId")

@Mapping(target = "projectMemLogJpaEntityId.version", source = "version")

UP4ProjectMemLogJpaEntity toEntity(UP4ProjectMemLog projectMemLog);

```

  

- 修正後產生的 `UP4ProjectMemLogMapperImpl` 會先建立主鍵物件、填入三個欄位，再設定到 Entity 上。

- `toDomain()` 原本就正常：Entity 已有 `getProjectId()` 等方法，MapStruct 會直接使用。

- 修正後 `up` 模組編譯成功，所有 mapper 都沒有 `Unmapped target property` 警告。

  

### 通則

  

Domain 物件是平的欄位，JPA Entity 用 `@EmbeddedId` 包成複合主鍵物件時，MapStruct 不會自動把平的欄位組成主鍵物件，`toEntity()` 必須用 `@Mapping(target = "<主鍵欄位>.<欄位>", source = "<欄位>")` 明確對應。其他使用複合主鍵的 Entity（如 `Up4ProjectRolMem`、`Up4ProjectTaskMem`）新增 mapper 時也要注意。

  

## 部署前需建立的 SEQUENCE

  

MSSQL 與 Oracle 語法相同：

  

```sql

CREATE SEQUENCE SEQ_UP4_PROJECT     START WITH 1 INCREMENT BY 1;

CREATE SEQUENCE SEQ_UP4_PROJECT_KEY START WITH 1 INCREMENT BY 1;

```

  

- SEQUENCE 名稱請用大寫（Oracle 會把未加引號的名稱轉為大寫）。

- SEQUENCE 有快取，重新啟動資料庫後**可能跳號，但不會重複**。若要求不可跳號，Oracle 加 `NOCACHE`、MSSQL 加 `NO CACHE`，代價是效能較差。

- MSSQL 需 2012 以上版本。
