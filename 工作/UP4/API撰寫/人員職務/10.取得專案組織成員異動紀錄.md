# 實作 `getProjectMemberChangeHistory`（[10] 取得專案組織成員異動紀錄）

  

## 目標

  

照 `up` 模組現有的分層寫法（參考 `getProjectOrgTreeOfAF`），完成：

  

- **API**：`POST /up/api/project/org/employees/history`

- **資料來源**：`UP4_PROJECT_MEM_LOG`（已有 `UP4ProjectMemLog`、`UP4ProjectMemLogJpaEntity`、`ProjectMemberActivity`）

- **需求**：多條件篩選、分頁（`pageSize = -1` 取全部）、排序

  

> 異動紀錄保存的是「異動當時」的姓名、職務、組織，**直接查 LOG 表，不 join 其他表**，避免職務改名或刪除後對應不到。

## API 規格

  

### Request

  

```json

{

    "pageSize": 3,

    "page": 1,

    "projectId": "PRJXXX",

    "keyword": "",

    "orgId": "company",

    "isPartner": false,

    "activity": ["join", "leave"],

    "rolName": ["設計"],

    "order": "ascend",

    "sort": "updatedAt"

}

```

  

| 欄位 | 說明 | 篩選語意 |

| --- | --- | --- |

| `pageSize` | 頁面大小 | `-1` 取全部 |

| `page` | 第幾頁 | 從 1 開始 |

| `projectId` | 專案 ID | 必填 |

| `keyword` | 名稱關鍵字 | 空字串找全部 |

| `orgId` | 篩選 org id | 空值不篩選 |

| `isPartner` | 是否為企業夥伴 | `null` 不篩選 |

| `activity` | `join` / `leave`，可複選 | `null` 或空陣列＝全選 |

| `rolName` | 職務名稱，可複選 | **`null` 全選、空陣列全不選** |

| `order` | `ascend` / `descend` | |

| `sort` | 排序欄位 | 目前只有 `updatedAt` |

## 整體流程

  

```text

POST /up/api/project/org/employees/history

  ProjectMemberController                     adapter.web        接收 request、轉成 response

    → GetProjectMemberHistoryUseCase          application        使用情境介面

    → GetProjectMemberHistoryService          application        業務規則（篩選語意）

    → ProjectMemberHistoryQueryPort           application.query  「我需要什麼資料」

    → JpaProjectMemberHistoryQueryPortAdapter infrastructure     「怎麼查」（Specification + Pageable）

```

  

**為什麼用 Specification？** 這支 API 有 6 個可選的篩選條件，用方法名稱推導（`findByXxxAndYyy`）會有太多組合；Specification 可以依條件動態組出 `WHERE`。

### 4-2 實作 Query Port

  

`infrastructure/persistence/jpa/repository/JpaProjectMemberHistoryQueryPortAdapter.java`

  

```java

package com.flowring.up.infrastructure.persistence.jpa.repository;

  

import com.flowring.up.application.query.ProjectMemberHistoryCriteria;

import com.flowring.up.application.query.ProjectMemberHistoryQueryPort;

import com.flowring.up.application.result.PageResult;

import com.flowring.up.domain.model.entity.UP4ProjectMemLog;

import com.flowring.up.infrastructure.persistence.jpa.entity.UP4ProjectMemLogJpaEntity;

import com.flowring.up.infrastructure.persistence.jpa.mapper.UP4ProjectMemLogMapper;

import jakarta.persistence.criteria.Predicate;

import lombok.RequiredArgsConstructor;

import org.springframework.data.domain.Page;

import org.springframework.data.domain.PageRequest;

import org.springframework.data.domain.Sort;

import org.springframework.data.jpa.domain.Specification;

import org.springframework.stereotype.Component;

import org.springframework.util.StringUtils;

  

import java.util.ArrayList;

import java.util.List;

  

@Component

@RequiredArgsConstructor

public class JpaProjectMemberHistoryQueryPortAdapter implements ProjectMemberHistoryQueryPort {

  

    private final SpringDataUP4ProjectMemLogRepository springDataRepository;

    private final UP4ProjectMemLogMapper up4ProjectMemLogMapper;

  

    @Override

    public PageResult<UP4ProjectMemLog> search(ProjectMemberHistoryCriteria c) {

        Specification<UP4ProjectMemLogJpaEntity> spec = toSpec(c);

        Sort.Direction direction = c.ascending() ? Sort.Direction.ASC : Sort.Direction.DESC;

        // 加 logId 當第二排序，同一時間的資料分頁才不會跳動

        Sort sort = Sort.by(direction, "updatedAt").and(Sort.by(direction, "logId"));

  

        // pageSize = -1 取全部

        if (c.unpaged()) {

            List<UP4ProjectMemLog> list = springDataRepository.findAll(spec, sort).stream()

                    .map(up4ProjectMemLogMapper::toDomain)

                    .toList();

            return new PageResult<>(1, -1, list.size(), list.isEmpty() ? 0 : 1, list);

        }

  

        // 前端 page 從 1 開始，Spring 從 0 開始

        Page<UP4ProjectMemLogJpaEntity> page = springDataRepository.findAll(

                spec, PageRequest.of(c.page() - 1, c.pageSize(), sort));

        return new PageResult<>(

                c.page(),

                c.pageSize(),

                page.getTotalElements(),

                page.getTotalPages(),

                page.getContent().stream().map(up4ProjectMemLogMapper::toDomain).toList());

    }

  

    private Specification<UP4ProjectMemLogJpaEntity> toSpec(ProjectMemberHistoryCriteria c) {

        return (root, query, cb) -> {

            List<Predicate> predicates = new ArrayList<>();

            predicates.add(cb.equal(root.get("projectId"), c.projectId()));

  

            if (StringUtils.hasText(c.keyword())) {

                predicates.add(cb.like(cb.lower(root.get("memName")), "%" + c.keyword().toLowerCase() + "%"));

            }

            if (StringUtils.hasText(c.orgId())) {

                predicates.add(cb.like(root.get("orgPathId"), "%" + c.orgId() + "%"));

            }

            if (c.isPartner() != null) {

                predicates.add(cb.equal(root.get("isPartner"), c.isPartner()));

            }

            if (c.activities() != null && !c.activities().isEmpty()) {

                predicates.add(root.get("activity").in(c.activities()));

            }

            if (c.rolNames() != null) {

                predicates.add(root.get("rolName").in(c.rolNames()));

            }

            return cb.and(predicates.toArray(Predicate[]::new));

        };

    }

}

```

  

> **注意**

> - `root.get("...")` 放的是 **Entity 欄位名稱**，不是 DB 欄位名稱。

> - `activity` 已有 `ProjectMemberActivityConverter`，直接傳 enum 進 `in()` 即可。

  

> **常見編譯錯誤**

>

> | 錯誤訊息 | 原因 | 修正 |

> | --- | --- | --- |

> | `no suitable method found for findAll(Specification<...JpaEntity>, Sort)` | `JpaSpecificationExecutor<T>` 的 `T` 放成 domain 物件 `UP4ProjectMemLog` | 改成 `JpaSpecificationExecutor<UP4ProjectMemLogJpaEntity>`，`T` 必須和 `JpaRepository<T, ID>` 相同 |

> | `jakarta.persistence.criteria.Predicate cannot be converted to java.util.function.Predicate` | IDE 自動 import 選錯同名類別 | import `jakarta.persistence.criteria.Predicate` |

### ProjectMemberHistoryMapper

  

Web Mapper 負責 **進出兩個方向** 的轉換，讓 Controller 保持單純：

  

```text

ProjectMemberHistoryMapper

  toCriteria(Request)     Request → Criteria    進 UseCase 前

  toPageResponse(Result)  Result  → Response    UseCase 回傳後

```

  

- **進**：字串轉 enum、`page` 最小值、`ascend` 判斷。

- **出**：時間格式、enum 轉字串，屬於 **API 呈現**，不放進 Service。

  

> 與既有的 `RenameProjectRolMapper.toCommand(...)` 寫法一致。

  

`adapter/web/mapper/ProjectMemberHistoryMapper.java`

  

```java

package com.flowring.up.adapter.web.mapper;

  

import com.flowring.up.adapter.web.dto.request.ProjectMemberHistoryRequest;

import com.flowring.up.adapter.web.dto.response.PageResponse;

import com.flowring.up.adapter.web.dto.response.ProjectMemberHistoryResponse;

import com.flowring.up.application.query.ProjectMemberHistoryCriteria;

import com.flowring.up.application.result.PageResult;

import com.flowring.up.domain.model.entity.UP4ProjectMemLog;

import com.flowring.up.domain.model.enums.ProjectMemberActivity;

import org.mapstruct.Mapper;

import org.mapstruct.Mapping;

import org.mapstruct.Named;

  

import java.time.Instant;

import java.time.ZoneId;

import java.time.format.DateTimeFormatter;

import java.util.List;

  

@Mapper(componentModel = "spring")

public interface ProjectMemberHistoryMapper {

  

    DateTimeFormatter FORMATTER = DateTimeFormatter.ofPattern("yyyy-MM-dd HH:mm").withZone(ZoneId.of("Asia/Taipei"));

  

    // Request -> Criteria（進 UseCase 前）避免 UseCase 依賴 adapter 層違反 ArchUnit 規則

    default ProjectMemberHistoryCriteria toCriteria(ProjectMemberHistoryRequest r) {

        List<ProjectMemberActivity> activities = r.activity() == null ? null

                : r.activity().stream().map(ProjectMemberActivity::fromCode).toList();

        return new ProjectMemberHistoryCriteria(

                r.projectId(),

                r.keyword(),

                r.orgId(),

                r.isPartner(),

                activities,

                r.rolName(),

                Math.max(r.page(), 1),

                r.pageSize(),

                "ascend".equals(r.order()));

    }

  

    // Result -> Response（UseCase 回傳後）

    @Mapping(target = "updatedAt", source = "updatedAt", qualifiedByName = "formatTime")

    @Mapping(target = "activity", source = "activity", qualifiedByName = "activityCode")

    ProjectMemberHistoryResponse toResponse(UP4ProjectMemLog log);

  

    default PageResponse<ProjectMemberHistoryResponse> toPageResponse(PageResult<UP4ProjectMemLog> result) {

        PageResult<ProjectMemberHistoryResponse> mapped = result.map(this::toResponse);

        return new PageResponse<>(mapped.page(), mapped.pageSize(), mapped.total(), mapped.totalPage(), mapped.list());

    }

  

    @Named("formatTime")

    default String formatTime(Long epochMillis) {

        return epochMillis == null ? null : FORMATTER.format(Instant.ofEpochMilli(epochMillis));

    }

  

    @Named("activityCode")

    default String activityCode(ProjectMemberActivity activity) {

        return activity == null ? null : activity.getCode();

    }

}

```

## Step 6：Controller

  

把 `ProjectMemberController` 裡 `[10]` 的空殼換成以下內容。Controller 只做三件事：**收 request、呼叫 UseCase、回傳 response**；兩個方向的轉換都交給 `ProjectMemberHistoryMapper`（見 Step 5）。

  

```java

private final GetProjectMemberHistoryUseCase getProjectMemberHistoryUseCase; // 10 取得專案組織成員異動紀錄

private final ProjectMemberHistoryMapper projectMemberHistoryMapper;

  

/**

 * [10] 取得專案組織成員異動紀錄

 * 專案職務人員有異動時必須完整記錄異動當時的資料，不可用 roleId 去 join 名稱之類的，避免異動或刪除會對應不到。

 */

@PostMapping("/org/employees/history")

@PreAuthorize("isAuthenticated()")

public ApiResponse<PageResponse<ProjectMemberHistoryResponse>> getProjectMemberChangeHistory(

        @Valid @RequestBody ProjectMemberHistoryRequest request) {

    PageResult<UP4ProjectMemLog> result = getProjectMemberHistoryUseCase.execute(projectMemberHistoryMapper.toCriteria(request));

    return ApiResponse.success(projectMemberHistoryMapper.toPageResponse(result));

}

```

  

> **為什麼一定要轉成 Criteria，不能讓 UseCase 直接收 Request？**

> 那樣 application 層就會依賴 adapter 層，`ArchitectureTest` 的分層規則不允許任何一層依賴 adapter，測試會失敗。轉換一定要做，但放在 Mapper 就好，不必寫在 Controller。

## Criteria 與 port 兩者的關係

  

不一樣，兩個是不同的角色：

  

- ProjectMemberHistoryCriteria 是「資料」，也就是要查什麼。

- ProjectMemberHistoryQueryPort 是「介面」，也就是誰去查、怎麼呼叫。

  

對照

  

| 比較項目 | ProjectMemberHistoryCriteria | ProjectMemberHistoryQueryPort |

| :--- | :--- | :--- |

| **型別** | record，只有欄位 | interface，只有方法 |

| **角色** | 查詢條件（參數物件） | 查詢的契約（抽象） |

| **回答的問題** | 「要查哪些資料？」 | 「誰可以幫我查？」 |

| **有沒有實作** | 沒有，就是一包值 | 由 `JpaProjectMemberHistoryQueryPortAdapter` 實作 |

| **比喻** | 點餐單 | 點餐窗口 |

  
  
  
  

Criteria 是 Port 方法的參數：

  

public interface ProjectMemberHistoryQueryPort {

    PageResult<UP4ProjectMemLog> search(ProjectMemberHistoryCriteria criteria);

    //     ↑ 回傳結果                         ↑ 查詢條件

}

  

在流程裡的位置

  

Controller

  │  mapper.toCriteria(request)                   ← 產生 Criteria（點餐單）

  ▼

Service

  │  queryPort.search(criteria)                   ← 透過 Port（窗口）送出

  ▼

JpaProjectMemberHistoryQueryPortAdapter           ← 實作 Port（廚房）

  │  toSpec(criteria) → Specification → SQL       ← 讀 Criteria，轉成 SQL 條件

  ▼

DB

  

為什麼要分開？

  

- Port 解決的是依賴方向。 Service 只認識介面，不認識 JPA。以後換資料來源，只要換掉 Adapter。

- Criteria 解決的是參數太多。 如果不用 Criteria，search(...) 會有 9 個參數，很難讀，也很容易傳錯順序。包成一個物件後，加條件只要加欄位，方法簽章不用改。

## 命名習慣

  

專案裡大致有這幾種：

  

- XxxQueryPort：查詢用的介面，放在 application/query。

- XxxCriteria / XxxQuery：查詢條件，放在 application/query。

- XxxCommand：寫入用的輸入，例如 RenameProjectRolCommand，放在 application/command。

- XxxResult：輸出，例如 PageResult，放在 application/result。

  

Criteria 和 Port 放在同一個 application/query 資料夾，是因為它們都屬於「查詢」這個主題，不是因為它們是同一個東西。## 後記
