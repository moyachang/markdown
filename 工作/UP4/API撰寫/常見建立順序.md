以 Clean Architecture（乾淨架構）的開發習慣來說，<mark style="background:#d3f8b6">寫程式通常會遵循「由內而外（Inside-Out）」**或**「依賴方向（Dependency Rule）」的原則</mark>：也就是先建立最核心、不依賴別人的資料結構與介面，最後才寫外層的 Controller 與轉換器。

依照圖片中的架構，一般工程師最順暢的實作與編寫順序如下：

### 第一階段：Domain / Application 核心資料與介面（最內層）

這時候先定義好「我們要回傳什麼格式」以及「我們要跟資料庫索取什麼介面」，這個階段不需要依賴任何外部實作。

1. **`result`（資料結果模型）**
    _最底層的 DTO/Record，其他類別會需要用到它們的型別來承載資料。_
    - **`PartnerMemberDetail`**
    - **`ProjectPartnerMemberExportResult`**
    
2. **介面/Port**
    _定義商業邏輯需要什麼方法（介面），還不需要寫實作
    - 查詢(讀取): QueryPort、LoadPort
	    - ==🟢負責資料讀取，不會改變資料狀態。==
	    - ==🔴預設採用 "QueryPort"==
	    - 實作命名則會是 "xxxxx==🟠QueryAdapter=="
    - 新刪修(寫入): CommandPort、PersistencePort 
	    - ==🟢負責寫入或變更資料狀態，通常會包在 @Transaction 中==
	    - 預設採用 "==🔴CommandPort=="
	    - 實作命名則會是 "xxxxx==🟠CommandAdapter=="
    - 特定單一寫入動作: savePort、UpdatePort、DeletePort 當專案拆更細時，會直接用動詞命名單一職責的介面
3. **`Application`（商業邏輯與 UseCase）**
    _核心的商業邏輯，串接 Port 來取得資料並進行處理。_
    - **`ExportProjectPartnerMemberUseCase`**（通常是 Interface）
    - **`ExportProjectPartnerMemberService`**（實作 UseCase）
    - 

### 第二階段：Infras 外部設施層（資料庫存取實作）

有了介面之後，就可以去實作如何跟資料庫溝通。

4. **`Infras`**
    
    - **`JpaPartnerMemberDetail1QueryPortAdapter`**
    - _原因：實作第一階段定義好的 `QueryPort`，實際去寫 JPA / SQL 撈出資料。_

### 第三階段：Adapter 介面層 / Controller（最外層）

當核心商業邏輯與資料庫都能運作後，最後才處理對外接收請求、轉換格式與回應的部分。

5. **`Adapter`**
    
    - **`ProjectPartnerMemberExportMapper`**
        - _原因：負責把 Application 產生的 Result 轉換成前端/外部看得懂的 Response 格式。_
    - **`ProjectPartnerMemberExportResponse`**
        - _原因：定義外層的回應物件結構。_
    - **`ProjectMemberExportController`**
        - _原因：最外層的 API 入口點（Entry Point），呼叫 UseCase 並回傳 Response，通常是整個功能最後串接完成的地方。_

1. `result` (`PartnerMemberDetail`, `ProjectPartnerMemberExportResult`)
2. `query` (`PartnerMemberDetail1QueryPort`)
3. `Application` (`ExportProjectPartnerMemberUseCase` / `ExportProjectPartnerMemberService`)
4. `Infras` (`JpaPartnerMemberDetail1QueryPortAdapter`)
5. `Adapter` (`ProjectPartnerMemberExportMapper`, `ProjectPartnerMemberExportResponse`)
6. `Adapter` (`ProjectMemberExportController`)
