從這行程式碼看得出來，您正在使用 **Java 17 / Java 21** 所引進的 **Sealed Classes / Interfaces（密封類別與介面）** 語法！

  

以下為您解析這行語法的設計意圖、優勢以及在您目前的專案（如剛才的 `ProjectRoleTreeAssembler`）中扮演的角色：

  

## 1. 語法拆解與含義

Java

```
public sealed interface RoleMember permits MemberInfo, MemberInfoManual {
```

- **`sealed interface RoleMember`**：
    
    宣告一個**密封介面**（Sealed Interface）。這意味著這個介面**不能被隨意實作（Implement）**。
    
      
    
- **`permits MemberInfo, MemberInfoManual`**：
    
    明確指定**只有** `MemberInfo` 與 `MemberInfoManual` 這兩個類別（或介面）有權限實作 `RoleMember` 介面。其他任何類別若嘗試 `implements RoleMember`，編譯器都會直接報錯！
    
      
    

## 2. 為什麼要在這個領域（專案角色/人員）這樣設計？

在您的業務情境中，專案裡的「角色成員（Role Member）」可能來自兩種不同的來源：

  

1. **`MemberInfo`**：系統內部的正式組織人員（例如從組織樹選入的員工，帶有 `memType = "ORG"`）。
    
      
    
2. **`MemberInfoManual`**：手動新增/外部產生的成員（例如外包人員、臨時人員、廠商代表等）。
    
      
    

使用 `sealed interface` 的主要好處有：

  

### 💡 好處一：多型（Polymorphism）與領域抽象

無論成員是正式員工還是手動輸入的外部人員，他們在「專案角色樹（Role Tree）」中都是同一個節點（掛在某個 `Role` 下）。

透過 `RoleMember` 介面，您的 `RoleTreeResult` 或 `Assembler` 就可以寫成：

  

Java

```
// 泛化處理所有的角色成員，不必拆成兩個 List
public record RoleTreeResult(
    String id,
    String name,
    List<RoleMember> employees, // 可以同時容納 MemberInfo 與 MemberInfoManual
    List<RoleTreeResult> children
) {}
```

### 💡 好處二：模式匹配與完整的編譯檢查（Pattern Matching for switch）

在 Java 21 中，當您搭配 `switch` 使用密封介面時，編譯器知道 `RoleMember` 的實作**只有兩種可能**。因此您不需要寫 `default` 分支，且如果未來新增了第三種成員型態卻忘記處理，編譯器會自動提示！

  

Java

```
public String getDisplayTitle(RoleMember member) {
    return switch (member) {
        case MemberInfo orgMem -> "正式員工: " + orgMem.name();
        case MemberInfoManual manualMem -> "外包人員: " + manualMem.name();
        // 不需要寫 default，因為編譯器知道只有這兩種實作！
    };
}
```

### 💡 好處三：領域邊界控制（Domain Boundaries）

防止團隊中的其他開發者在不了解領域邏輯的情況下，隨意寫一個 `class CustomMember implements RoleMember` 破壞了系統對成員類型的嚴謹定義。

  

## 3. 實作時的注意事項

實作 `RoleMember` 的類別（`MemberInfo` 與 `MemberInfoManual`）必須滿足以下三個條件之一：

  

1. **宣告為 `final`**（最常見，例如 Java 16+ 的 `record` 預設就是 `final`）：
    
      
    
    Java
    
    ```
    public final record MemberInfo(...) implements RoleMember {}
    public final record MemberInfoManual(...) implements RoleMember {}
    ```
    
2. **宣告為 `sealed`**：繼續限制其子類別。
    
      
    
3. **宣告為 `non-sealed`**：開放其他人繼續繼承/實作。
    
      
    

### 總結

這是一個非常現代、優雅且符合 DDD **代數資料型態（Algebraic Data Types / Sum Types）** 的設計手法！它讓程式碼既能享受多型帶來的彈性，又具備強型別的嚴謹度與編譯期安全性。
