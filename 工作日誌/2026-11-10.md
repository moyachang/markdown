### 有預設值的
建立日期及更新日期，建立時就要初始的內容。可使用 @PrePersist
更新日期是有更新才記錄。 可使用 @PreUpdate
如此，mapper 就不需要處理這些轉換。

```java
// 20261110 加入  
@Column(name = "CREATED_AT", nullable = false, updatable = false)  
private long createdAt;  
  
@PrePersist  
public void prePersist() {  
    long currentTime = System.currentTimeMillis();  
    updatedAt = currentTime;  
    createdAt = currentTime;  
}  
  
@PreUpdate  
public void preUpdate() {  
    updatedAt = System.currentTimeMillis();  
}
```

### 使用 Enum
若沒有使用 converter 的話，則需要宣告 @Enumerated(EnumType.STRING)
但因為我有寫，所以就沒什麼事。
```java
@Builder.Default

@Enumerated(EnumType.STRING)

@Column(name = "ROL_TYPE", length = 30, nullable = false)

private ProjectRoleType rolType = ProjectRoleType.CUSTOM;
```

如果不寫 `@Enumerated(EnumType.STRING)`，JPA / Hibernate 預設會使用 **`EnumType.ORDINAL`**（即儲存 Enum 的**索引值**，從 0 開始，例如 `OWNER` = 0、`MANAGER` = 1、`CUSTOM` = 2）。

  

這會對你的系統造成以下幾種**重大影響**：

  

### 1. 資料庫儲存內容變成「數字」而非「文字」

- **有寫 `@Enumerated(EnumType.STRING)`**： 資料庫中該欄位（`ROL_TYPE`）存的是字串，例如：`"OWNER"`、`"MANAGER"`、`"CUSTOM"`。
    
      
    
- **沒寫 `@Enumerated(EnumType.STRING)`**： 資料庫中存的是數字，例如：`0`、`1`、`2`。
    
      
    

### 2. 未來調整 Enum 順序會導致「資料嚴重錯亂」

這是使用 `ORDINAL` 最致命的問題。假設你原本的 Enum 定義是：

  

Java

```
public enum ProjectRoleType {
    OWNER,   // 0
    MANAGER, // 1
    CUSTOM   // 2
}
```

如果日後因為業務需求，在最前面加了一個新的角色 `ADMIN`：

  

Java

```
public enum ProjectRoleType {
    ADMIN,   // 0 (新加入)
    OWNER,   // 1 (原本是 0)
    MANAGER, // 2 (原本是 1)
    CUSTOM   // 3 (原本是 2)
}
```

- **災難發生**：原本資料庫裡存著 `0`（代表 `OWNER`）的舊資料，Hibernate 讀取時會把它對應到新的第 0 個值 —— 也就是 **`ADMIN`**。這會導致舊使用者的權限直接被錯亂。
    
      
    
- **如果用 `STRING`**：資料庫存的是 `"OWNER"`，不管你在 Enum 裡面怎麼加、怎麼改順序、甚至刪除不用的，只要字串名稱對得上，資料就永遠不會亂。
    
      
    

### 3. 可讀性與維護性降低

- 當你直接去資料庫（如 MySQL）用 SQL 查詢（`SELECT * FROM project WHERE ROL_TYPE = 2`）時，你很難一眼看出這代表什麼角色。
    
      
    
- 如果存成字串（`ROL_TYPE = 'CUSTOM'`），一眼就能看出含意，對後續的除錯、手動修復資料庫或寫報表 SQL 非常友善。
    
      
    

### 💡 結論與建議

結合你目前的設定：

  

Java

```
@Builder.Default
@Column(name="ROL_TYPE", columnDefinition = "VARCHAR(30)", nullable = false)
private ProjectRoleType rolType = ProjectRoleType.CUSTOM;
```

你的 `@Column` 已經明確指定了 `columnDefinition = "VARCHAR(30)"`，這代表你的**資料庫欄位型態是字串（VARCHAR）**。

  

- **如果你不寫 `@Enumerated(EnumType.STRING)`**： Hibernate 會嘗試把 Enum 的整數索引（`0`、`1`、`2`）塞進一個 `VARCHAR(30)` 的欄位裡（通常會自動轉成字串 `"0"`、`"1"`、`"2"` 存進去）。這不僅不直觀，還會隱藏上述的維護風險。
    
      
    
- **強烈建議**：一定要加上 `@Enumerated(EnumType.STRING)`，讓程式碼與資料庫欄位完美契合，確保資料安全。
    

Java

```
@Builder.Default
@Enumerated(EnumType.STRING) // <--- 務必加上這行
@Column(name="ROL_TYPE", columnDefinition = "VARCHAR(30)", nullable = false)
private ProjectRoleType rolType = ProjectRoleType.CUSTOM;
```

這幾個名稱代表不同用途：

| 類型 | 用途 | 你目前的例子 |
|---|---|---|
| Request | 接收 HTTP 輸入 | `AddPermissionSettingRequest` |
| Command | 表達新增、修改、刪除操作的輸入 | `AddPermissionSettingCommand` |
| Query／Criteria | 表達查詢條件 | `PermissionCriteria` |
| QueryPort | 定義查詢能力的介面 | `Up4ModuleAuthQueryPort` |

**Request 的轉換由 mapper 負責，QueryPort 則負責提供查詢方法，兩者用途不同。**
