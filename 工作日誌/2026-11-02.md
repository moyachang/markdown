今天一來主要是處理日誌 sql 沒法出現參數的資料問題。
主要是我的 log 設定等級是 info
更精確地說，這裡有**兩層日誌篩選**：

1. **Logger 層級**：`org.hibernate.orm.jdbc.bind` 必須設為 `TRACE`，才會產生參數綁定訊息。
2. **Console Appender 篩選**：原本的 `console` 設了 `ThresholdFilter = INFO`，即使 Logger 已產生 TRACE 訊息，仍會被這一層擋掉。

所以，**單獨設定 `jdbc.bind = TRACE` 還不夠**。

目前的做法是在 `local` 環境使用另一個 **`consoleLocal`**（檔案中的實際名稱），移除 INFO 門檻，再搭配：

```xml
<logger name="org.hibernate.SQL" level="DEBUG"/>
<logger name="org.hibernate.orm.jdbc.bind" level="TRACE"/>
```

這樣才能看到 SQL 和參數值，而且必須確實啟用 `local` profile。

補充：**root 設為 INFO 本身不是阻擋原因**；明確指定 TRACE 的子 Logger 可以產生 TRACE 訊息。這次關鍵是原本 Console 上的 INFO `ThresholdFilter`。


WFCIService\src\main\resources\logback-spring.xml
新增本機用的 console
```java
<!-- 本機專用的控制台輸出：不設 ThresholdFilter，可顯示 Hibernate DEBUG / TRACE --><appender name="consoleLocal" class="ch.qos.logback.core.Console卜Appender">  
    <encoder>  
       <pattern>${CONSOLE_LOG_PATTERN}</pattern>  
       <charset>UTF-8</charset>  
    </encoder>  
</appender>
```
在 profile 設定-local 再加入以下幾行
```java
<!-- 只在 local 開啟 Hibernate SQL 與參數綁定的 log --><logger name="com.flowring.modules.api.dao" level="DEBUG"/>  
<logger name="org.hibernate.SQL" level="DEBUG"/>  
<!-- Hibernate 6+ 適用；舊版 Hibernate 改用 org.hibernate.type.descriptor.sql.BasicBinder --><logger name="org.hibernate.orm.jdbc.bind" level="TRACE"/>  
  
<!--必选节点，用来指定最基础的日志输出级别-->  
<root level="INFO">  
    <appender-ref ref="logInfoFile"/>  
    <appender-ref ref="consoleLocal"/>  
</root>
```

WFCIService\src\main\resources\application.yml
把原本的 logging 的設定刪掉，加一行註解
```java
# SQL / Hibernate 參數 log 只在 local profile 開啟，設定在 logback-spring.xml 的 <springProfile name="local">
```

----
1. WFCIService/src/main/resources/logback-spring.xml

- 加了一個本機專用的 consoleLocal appender。它沒有 ThresholdFilter，所以 TRACE 也會印在 Console。
- 原本的 console（只顯示 INFO 以上）完全沒動，dev、pro 還是用它。
- local 的 root 從 console 換成 consoleLocal，並在 local 區塊裡加上這幾個 logger：

<springProfile name="local">
    <logger name="com.flowring.modules.api.dao" level="DEBUG"/>
    <logger name="org.hibernate.SQL" level="DEBUG"/>
    <logger name="org.hibernate.orm.jdbc.bind" level="TRACE"/>
    <root level="INFO">
        <appender-ref ref="logInfoFile"/>
        <appender-ref ref="consoleLocal"/>
    </root>
</springProfile>

2. WFCIService/src/main/resources/application.yml

- 拿掉了 logging.level 那幾行（org.hibernate.SQL、org.hibernate.orm.jdbc.bind 等）。寫在 application.yml 的層級對所有 profile 都會生效。原本 dev/pro 的 Console 雖然被 INFO 擋住，但 logInfoFile 沒有過濾，TRACE 一樣會寫進正式環境的 log 檔。改成只寫在 local 區塊後，正式環境就不會受影響。

要注意的地方：

- 要記得切換 profile：現在 spring.profiles.active 是 mssql,dev。本機要看到 TRACE，要改成 mssql,local，或啟動時加 --spring.profiles.active=mssql,local。
- show-sql: true 我沒有動：它是直接用 System.out 印 SQL，不經過 logback，所以 dev/pro 也會印出來，而且跟 org.hibernate.SQL 的輸出會重複。建議改成 false，只靠 logger 輸出。
- local 的 log 檔也會有 TRACE：local 的 log 檔一樣會寫進 TRACE。如果只想讓 Console 顯示 TRACE、檔案維持 INFO，可以在 logInfoFile 加一個 INFO 的 ThresholdFilter。

**目前 `toResult()` 放在 Service 裡是合適的，不必為了分層就拆出去。** 它是這個匯出用例的私有轉換方法，將查詢結果組成 `ProjectOrgMemberExportResult`，屬於應用層的工作。

不過，它裡面實際包含三種責任：

| 內容 | 目前放這裡是否合理 |
|---|---|
| 組裝匯出結果、把空值轉為 `""` | 合理，是匯出格式需求 |
| 根據 `mobilePhoneOpen` 決定是否輸出手機 | 合理，但若其他用例也使用，應統一規則 |
| 拆解 `mainRolePath`，取得部門與職務 | 可以；若多處重複，值得抽出共用邏輯 |

你附上的 `RolePosition` 也有拆解 `>>` 路徑的邏輯，但**不建議把整個 `toResult()` 搬進 `RolePosition`**。那會讓 Domain 的 VO 依賴 Application 的匯出結果類別，依賴方向就反了。

而且目前兩者的行為不同：

- `RolePosition.getRoleNameWithParentDep()` 產生「部門(職務)」，空路徑時回傳 `roleName`。
- `toResult()` 分別輸出部門與職務，空路徑時兩欄都留空。

**我的建議是目前保留 `toResult()`。** 如果之後多個地方都要解析組織路徑，再抽出專門的路徑 VO，統一「取得部門／職務」的規則；若匯出欄位轉換持續變複雜，再移到 Application 層的 assembler。
