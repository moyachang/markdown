
要，**註解掉不等於一定安全**。要看它是不是還會被 Spring 掃到、還有沒有 Bean/Filter 真的會載入。

你這幾個檔案可以先這樣判斷：

| 檔案              | 目前狀態                                             | 要不要先處理                      |
| --------------- | ------------------------------------------------ | --------------------------- |
| `ShiroConfig`   | `@Configuration` 被註解，但類別裡還有 `@Bean`              | **要確認**，如果沒人引用可刪掉或移出掃描範圍    |
| `RedisConfig`   | `@Configuration` 沒註解、而且有 `@Bean`                 | **要先處理**，這個很可能會啟動就生效        |
| `KaptchaConfig` | `@Configuration` 被註解                             | 若沒用到，**可先留著但別讓它被掃到**        |
| `CorsConfig`    | `@Configuration` 被註解                             | 若真的已移到新設定，可先不動              |
| `FilterConfig`  | `@Configuration` 被註解，但有 `FilterRegistrationBean` | **要確認**，因為 Filter 很常還是會影響啟動 |
| `SysConfig`     | 不是整個 class 廢棄，只有部分方法 deprecated                  | **要看那些方法有沒有被呼叫**            |

**原則很簡單：**
- **只有註解 `@Deprecated`：還是可能被載入。**
- **`@Configuration` / `@Component` / `@Bean` 還在：就可能影響啟動。**
- **整個類別被註解掉，但裡面還有 Bean：如果這個 class 仍在 component scan 範圍，通常就不會生效；但如果之後有人把註解拿掉，問題又會回來。**

**所以第一步不是清全部 Deprecated，**而是先做這件事：
1. 找出還會被 Spring 掃描到的 `@Configuration` 類別
2. 確認它們有沒有真的被引用
3. 沒用的就刪掉或明確排除
4. 會用到的就改成 Boot 4 相容寫法
